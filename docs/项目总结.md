# Personal Office Agent 项目总结

更新时间：2026-08-04

## 1. 项目定位

Personal Office Agent 是一个个人 AI 办公助手，支持：

- 个人知识库上传、解析、向量化、RAG 问答
- 多项目隔离
- LangGraph 多 Agent 编排
- MCP 工具调用
- 长期记忆
- 企业微信通知
- 文件夹同步
- 全局搜索
- 通知中心
- 暗色模式
- 后台任务
- 图片识别，MIMO v2.5

## 2. 技术栈

- Python 3.11
- FastAPI
- SQLAlchemy
- PostgreSQL
- Qdrant
- Redis
- LangGraph
- OpenAI / DeepSeek API
- MCP Python SDK

## 5. 核心功能说明

### 5.1 用户系统

用户注册后自动创建“默认项目”。登录使用 JWT，前端保存 token。

### 5.2 项目隔离

每个项目有独立知识库和聊天历史。上传、删除、RAG 检索、聊天历史都按 `project_id` 隔离。

### 5.3 文件上传

上传流程：

```text
用户上传文件
  -> FastAPI 保存本地文件
  -> 写入 Redis 队列
  -> 前端立即返回“已加入队列”
  -> Worker 后台解析文件
  -> 切片
  -> Embedding
  -> 写入 Qdrant
  -> 写入 PostgreSQL
  -> 发送通知
```

支持格式：

- PDF
- DOCX
- TXT
- MD
- XLSX
- PPTX
- PY
- JAVA
- CSV
- JSON
- PNG/JPG/JPEG/GIF/WEBP/BMP

### 5.4 RAG 问答

用户问题进入 LangGraph，Router 路由到 Knowledge Agent，Knowledge Agent 从 Qdrant 检索知识库，再由 DeepSeek 生成回答。

### 5.5 Agent 系统

- Router Agent：判断任务类型
- Knowledge Agent：知识库检索和回答
- Browser Agent：联网搜索、日期、时间
- Document Agent：生成 Word/Excel/PPT
- Workflow Agent：多步骤任务

### 5.6 MCP 工具

当前 10 个工具：

```text
file_search
file_read
file_create
browser_search
browser_open
excel_read
excel_analyze
github_analyze
github_generate_readme
wechat_notify
```

所有工具参数会注入 DeepSeek 系统提示词，AI 可以自主调用。

### 5.7 长期记忆

自动保存：

- 专业
- 身份
- 项目经历
- 技能
- 常用目录
- 常用工具
- 偏好
- 技术栈

设置页可手动查看、添加、删除。

### 5.8 企业微信通知

支持两种配置方式：

- 设置页保存 Webhook
- 对话中临时提供 Webhook

`wechat_notify` 会自动读取设置中保存的 Webhook。

### 5.9 后台任务

`/tasks` 可创建后台 Agent 任务，任务状态和结果可查询。

### 5.10 通知中心

上传、删除、项目创建等操作会写入通知，前端通过 SSE 实时接收。

### 5.11 全局搜索

可搜索：

- 项目
- 文件
- 聊天记录

## 6. Redis + Worker / Celery 架构说明

### 6.1 当前实现

当前项目已实现：

```text
Redis：消息仓库，存放待处理的上传任务
Worker：后台线程从 Redis 取任务并执行
```

流程：

```text
用户上传后，FastAPI 只把任务丢进 Redis，立刻返回前端；
Worker 单独取出任务，慢慢解析、Embedding、写向量库和数据库。
```

优点：

- 上传不阻塞前端
- 失败时通知用户
- 文件、数据库、Qdrant 一致回滚
- 服务重启后 Redis 中未处理任务仍存在

当前限制：

- 当前 Worker 是进程内线程，不是独立 Celery 进程
- 多机扩展需要升级为 Celery

### 6.2 后续升级为 Redis + Celery

```text
Celery：真正干活的任务工人
Redis：中间消息仓库，存放待执行任务、任务状态
```

流程：

```text
用户上传后，FastAPI 只把任务丢进 Redis，立刻返回前端；
Celery 进程单独取出任务慢慢处理。
```

优点：

- 任务持久保存，服务重启任务不会消失
- 支持重试、失败记录、查看任务进度
- 支持分布式多机器扩容
- 上万并发上传也不会崩

缺点：

- 需要额外部署 Redis、Celery
- 架构更复杂

## 7. 完整运行流程

### 7.1 安装依赖

```bash
cd ..
conda activate poa
pip install -r requirements.txt
```

```bash
cd ../frontend
npm install
```

### 7.2 配置环境变量

```bash
cd ..
cp .env.example backend/.env
nano backend/.env
```

填写：

```text
LLM_BASE_URL=https://api.deepseek.com
LLM_API_KEY=你的密钥
LLM_MODEL=deepseek-v4-flash
JWT_SECRET=随机字符串
WECHAT_WEBHOOK_URL=你的企业微信Webhook
```

### 7.3 初始化数据库

```bash
cd ..
conda activate poa
python -m alembic upgrade head
```

### 7.4 启动后端

```bash
cd ..
conda activate poa
uvicorn backend.app.main:app --reload
```

后端地址：

```text
http://127.0.0.1:8000
```

接口文档：

```text
http://127.0.0.1:8000/docs
```

### 7.5 启动前端

新开一个终端：

```bash
cd ../frontend
npm run dev
```

打开：

```text
http://localhost:5173
```

### 7.6 Docker 部署

```bash
cd ../docker
docker compose up -d --build
```

### 7.7 Electron 打包

```bash
cd ../frontend
npm run build
npm run electron:build
```
