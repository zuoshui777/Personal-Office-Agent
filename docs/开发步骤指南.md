# Personal Office Agent — 开发步骤指南

> 这份文档告诉你：**先写哪个文件、再写哪个文件、写完后怎么验证**。
>
> 代码内容你自己写，这里只帮你规划先后顺序和验证方法。

---

## 总体路线（5 个阶段）

整个项目分成 5 个阶段，每个阶段都是一个完整的小闭环，写完就可以验证：

```
第一阶段：搭建基础骨架 → 第二阶段：实现后端核心 → 第三阶段：实现前端页面
→ 第四阶段：前后端联调 → 第五阶段：Agent + MCP 扩展
```

**建议按顺序来，不要跳。**

---

## 第一阶段：搭建基础骨架

**目标**：跑起一个空的 Web 后端，能在浏览器看到 "Hello World"。

这一步只有 3 个文件，是检验你的环境是否正常的最小闭环。

### 步骤 1.1 — 写配置文件

| 顺序 | 文件 | 写什么 |
|------|------|--------|
| 1 | `backend/app/core/config.py` | 读取环境变量的配置类，从 `.env` 读取数据库地址、密钥等。用 `pydantic-settings` 实现 |
| 2 | `backend/app/core/security.py` | JWT Token 的生成和验证函数、密码哈希函数。用 `python-jose` + `passlib` |

### 步骤 1.2 — 写数据库连接

| 顺序 | 文件 | 写什么 |
|------|------|--------|
| 3 | `backend/app/database/connection.py` | 创建 SQLAlchemy 引擎和 SessionLocal 工厂，提供一个 `get_db` 依赖函数 |

### 步骤 1.3 — 写主入口

| 顺序 | 文件 | 写什么 |
|------|------|--------|
| 4 | `backend/app/main.py` | 创建 FastAPI 实例，加一个 `GET /` 返回 `{"message": "Hello from POA"}`，包含 CORS 中间件配置 |

### ✅ 验证 Lv.1

```bash
# 已经写好了：config.py → security.py → connection.py → main.py

cd ~/桌面/PC_AI/personal-office-agent
source venv/bin/activate
uvicorn backend.app.main:app --reload
```

打开浏览器访问 `http://127.0.0.1:8000`，应该看到：

```json
{"message": "Hello from POA"}
```

然后访问 `http://127.0.0.1:8000/docs`，能看到 Swagger 文档页面。

> 看到这两个页面，说明 Python 环境、FastAPI、uvicorn 都正常。

## 第二阶段：实现后端核心

**目标**：让后端能连接数据库、上传文件、存储向量、接收聊天请求。

### 步骤 2.1 — 写数据库模型

这 5 个表一一对应项目里要存的数据，先写模型再写 API。

| 顺序 | 文件 | 写什么 |
|------|------|--------|
| 5 | `backend/app/models/user.py` | 用户表：id、username、password_hash、role、created_at |
| 6 | `backend/app/models/project.py` | 项目表：id、project_name、description |
| 7 | `backend/app/models/document.py` | 文档表：id、project_id、file_name、file_path、file_type、created_at |
| 8 | `backend/app/models/task.py` | 任务表：id、task_name、status、result、created_at |
| 9 | `backend/app/models/memory.py` | 记忆表：id、key、value、source |

### 步骤 2.2 — 写数据库初始化脚本

| 顺序 | 文件 | 写什么 |
|------|------|--------|
| 10 | `scripts/init_db.py` | 连接 PostgreSQL，调用 SQLAlchemy 的 `Base.metadata.create_all` 创建所有表 |

### ✅ 验证 Lv.2.1

```bash
# 先启动数据库
cd ~/桌面/PC_AI/personal-office-agent/docker
docker compose up -d
cd ..

# 再运行初始化脚本
python scripts/init_db.py
```

没有报错就说明数据库连接成功、5 张表都创建好了。

可以用数据库工具（如 DBeaver）连接 PostgreSQL 查看表结构，或者在终端执行：

```bash
docker exec -it personal-office-agent-postgres-1 psql -U poa -d poa -c "\dt"
```

应该看到 5 张表。

---

### 步骤 2.3 — 写向量数据库封装

| 顺序 | 文件 | 写什么 |
|------|------|--------|
| 11 | `backend/app/vector_store/qdrant.py` | 封装 Qdrant 客户端，提供：创建 Collection、插入向量、搜索向量的方法 |

### 步骤 2.4 — 写 Pydantic 模型（请求/响应的格式定义）

| 顺序 | 文件 | 写什么 |
|------|------|--------|
| 12 | `backend/app/schemas/chat.py` | 定义 ChatRequest（用户消息）和 ChatResponse（AI 回复）的格式 |
| 13 | `backend/app/schemas/task.py` | 定义 TaskCreateRequest 和 TaskStatusResponse 的格式 |

### 步骤 2.5 — 写业务服务层

| 顺序 | 文件 | 写什么 |
|------|------|--------|
| 14 | `backend/app/services/file_service.py` | 处理文件上传、存储路径分配、文件删除的逻辑 |
| 15 | `backend/app/services/document_service.py` | 调用知识库解析器，实现文档解析 + 切片 + Embedding 入库的流程 |
| 16 | `backend/app/services/agent_service.py` | 接收用户消息，调用 LangGraph Agent 工作流，返回流式结果 |

> 注意：第 16 步的 `agent_service.py` 依赖后面的 Agent 模块，这一步可以先写骨架（空的函数定义），等第四阶段再填充完整逻辑。

### 步骤 2.6 — 写 API 路由

| 顺序 | 文件 | 写什么 |
|------|------|--------|
| 17 | `backend/app/api/upload.py` | `POST /api/upload` — 接收上传的文件，调用 file_service 保存，调用 document_service 解析入库 |
| 18 | `backend/app/api/chat.py` | `POST /api/chat` — 接收用户消息，调用 agent_service 处理，返回结果。`GET /api/chat/stream` — SSE 流式返回 |
| 19 | `backend/app/api/task.py` | `POST /api/task` — 创建后台任务。`GET /api/task/{id}` — 查询任务状态 |

### 步骤 2.7 — 注册路由到 main.py

| 顺序 | 文件 | 做什么 |
|------|------|--------|
| 20 | `backend/app/main.py` | 在创建 FastAPI 实例后，把上面 3 个路由文件 `include_router` 进来 |

### ✅ 验证 Lv.2.2

```bash
uvicorn backend.app.main:app --reload
```

打开 `http://127.0.0.1:8000/docs`，应该能看到 5 个 API 接口：

- `GET /`
- `POST /api/chat`
- `GET /api/chat/stream`
- `POST /api/upload`
- `POST /api/task`
- `GET /api/task/{id}`

按顺序写完的路径：

```
config.py → security.py → connection.py → main.py(骨架)
          ↘
user.py → project.py → document.py → task.py → memory.py
          ↘
init_db.py
          ↘
qdrant.py
          ↘
chat.py(schema) → task.py(schema)
          ↘
file_service.py → document_service.py → agent_service.py
          ↘
upload.py(api) → chat.py(api) → task.py(api)
          ↘
main.py(注册路由)
```

## 第四阶段：前后端联调

**目标**：前端能调用后端的 API，实现真正的问答交互。

### 步骤 4.1 — 配置代理

| 顺序 | 文件 | 写什么 |
|------|------|--------|
| 37 | `frontend/vite.config.ts` | 在 Vite 配置中加入 proxy，把 `/api` 开头的请求转发到 `http://127.0.0.1:8000` |

### 步骤 4.2 — 写 Embedding 模块

| 顺序 | 文件 | 写什么 |
|------|------|--------|
| 38 | `embeddings/embedding.py` | 封装 BGE-M3 模型，提供一个 `embed_text(text)` 返回向量 |

### 步骤 4.3 — 写知识库处理

| 顺序 | 文件 | 写什么 |
|------|------|--------|
| 39 | `knowledge_base/parser.py` | PDF/DOCX/PPTX/TXT/MD 等文件的文本提取函数，图片用 PaddleOCR |
| 40 | `knowledge_base/chunker.py` | 把长文本切成 800 字一段的切片，每段重叠 100 字 |
| 41 | `knowledge_base/retriever.py` | 接收用户问题，embedding → Qdrant 搜 TopK → 重排序 → 返回 Top3 切片 |

### 步骤 4.4 — 写 LangGraph Agent

| 顺序 | 文件 | 写什么 |
|------|------|--------|
| 42 | `agent/state.py` | 定义 AgentState（TypedDict）：user_input、task_type、retrieved_docs、need_web、tool_result、final_answer |
| 43 | `agent/router_agent.py` | 用 LLM 判断用户意图，路由到 Knowledge / Browser / Document / Workflow |
| 44 | `agent/knowledge_agent.py` | 调用 retriever 检索知识库，把结果拼入 prompt 让 LLM 回答 |
| 45 | `agent/browser_agent.py` | 用 Playwright 打开网页搜索，提取内容后用 LLM 总结 |
| 46 | `agent/document_agent.py` | 调用 LLM 生成文档内容，调用 MCP 创建 Word/Excel/PPT 文件 |
| 47 | `agent/workflow_agent.py` | 复杂任务拆解成多步，依次调用子 Agent |

### 步骤 4.5 — 写 MCP 插件

| 顺序 | 文件 | 写什么 |
|------|------|--------|
| 48 | `mcp/hub.py` | MCP 调度中心，注册所有插件，根据 tool_name 分发调用 |
| 49 | `mcp/file_mcp.py` | 文件操作：搜索、读取、创建 |
| 50 | `mcp/browser_mcp.py` | 浏览器操作：搜索、打开网页 |
| 51 | `mcp/excel_mcp.py` | Excel 分析：读取、统计、生成图表 |
| 52 | `mcp/github_mcp.py` | GitHub 操作：分析仓库 |
| 53 | `mcp/wechat_mcp.py` | 企业微信通知 |

### 步骤 4.6 — 前端 Electron

| 顺序 | 文件 | 写什么 |
|------|------|--------|
| 54 | `frontend/src/electron/main.ts` | Electron 主进程：创建窗口、加载前端 |
| 55 | `frontend/src/electron/preload.ts` | Electron 预加载脚本：暴露文件读写等安全 API |

### ✅ 验证 Lv.4

写完后能够完整跑通一个流程：上传 PDF 文件 → 文件被解析 → Embedding 入库 → 在聊天框提问 → 后端 RAG 检索 → AI 回答返回到前端。
