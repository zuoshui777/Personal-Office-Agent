# Personal Office Agent — 产品需求文档（PRD）

> 版本：v1.1 整合版 · 项目类型：AI Agent 应用系统 · 目标：个人开发 / 简历项目 / 可扩展产品

---

## 1 产品概述

**英文名称**：Personal Office Agent（POA）
**中文名称**：私人办公智能体

POA 是一个运行于个人电脑（优先 Linux，兼容 Windows，未来支持 macOS）的 AI 智能办公助手。它整合本地知识库、大语言模型、Agent 任务规划、MCP 工具调用、浏览器自动化与多格式文档处理能力，帮助用户管理个人数字资产并自动完成复杂办公任务。核心理念为：**从 AI 回答问题升级为 AI 帮助用户完成工作。**

---

## 2 产品背景与用户痛点

随着个人数字资料不断增长（毕业论文、毕业设计、实验报告、课程资料、项目代码、PDF / Word / Excel 文档、简历资料、学习笔记等），用户面临三大痛点：

1. **信息难以查找**——不知道资料在哪，需花大量时间翻阅文件，例如想知道"我的毕业论文使用了哪些技术"，传统方式需打开论文、搜索关键词、查看代码再手动整理。
2. **个人知识无法复用**——项目经验、技术方案、实验结果、学习记录等成果沉淀在文件中，写简历和面试准备时需要重新整理。
3. **办公任务重复**——根据资料生成报告、总结 PDF、分析 Excel、制作 PPT 等大量机械工作可交由 Agent 自动完成。

---

## 3 用户画像

- **学生**：毕业论文管理、毕业设计整理、实验报告生成、答辩 PPT 制作、面试项目介绍生成。
- **程序员**：项目代码管理、README 生成、技术文档总结、GitHub 仓库分析。
- **办公人员**：Excel 数据分析、周报生成、会议纪要整理、PPT 制作。

---

## 4 产品目标与技术链路

**产品目标**：打造运行在个人电脑上的 AI 办公智能体，使其同时承担知识助手、文件助手、办公助手与自动化助手的角色。

**技术目标**：实现完整 AI 应用开发链路——用户界面 → 后端服务 → LLM 调用 → RAG 知识库 → Agent 工作流 → 工具调用 → 自动化执行 → 部署运行。

---

## 5 核心价值

传统 AI 的模式是：用户提问 → AI 回答 → 结束。POA 的模式是：用户提出目标 → Agent 规划 → 调用工具 → 执行任务 → 生成结果 → 保存产物。例如用户说"根据我的毕业论文生成答辩 PPT"，系统自动读取论文、提取章节、总结内容、生成 PPT 大纲、创建 PPT 文件并保存到指定目录。

---

## 6 产品形态

采用 Electron + React + TypeScript 构建桌面端应用，界面风格类似 ChatGPT Desktop / Claude Desktop。运行环境优先 Linux，兼容 Windows，未来支持 macOS。

---

## 7 核心功能设计

### 7.1 知识中心（Knowledge Center）

支持文件格式：PDF、DOCX、XLSX、PPTX、TXT、MD、PY、JAVA、图片（OCR）。提供上传、删除、重建索引、标签分类、项目归档、文件夹同步等能力。文件夹同步路径示例：`~/Documents/AI-Knowledge`，系统自动完成发现文件 → 解析 → 切片 → Embedding → 存入向量数据库的流水线。

### 7.2 AI 知识问答（Knowledge Agent）

负责 RAG 检索、文档理解、多文档聚合问答与引用来源返回。示例：用户问"我的 YOLO 项目有哪些改进点？"，系统同时检索论文、实验记录、训练日志和项目代码，综合生成答案。当知识库中无结果时，自动触发 Browser Agent 联网补充信息。

### 7.3 文档生成（Document Agent）

- **Word**：报告生成、论文总结、周报生成。
- **Excel**：通过 Pandas 进行数据分析，生成统计结果、图表与趋势分析报告。
- **PPT**：PPT 大纲生成与自动制作演示文稿。

示例：用户说"根据我的毕业设计生成简历项目描述"，Agent 读取论文、代码和实验结果，生成项目介绍、技术栈、个人职责和项目亮点。

### 7.4 Browser Agent

当本地知识不足时 Agent 自动联网。流程：用户需求 → 判断缺少信息 → Playwright 打开浏览器 → 搜索网页 → 提取内容 → 总结回答。支持 Google、Bing、GitHub、CSDN、知乎等站点，授权后可自动登录。

### 7.5 Workflow Agent

负责复杂任务拆解与多步骤编排。示例——生成答辩 PPT：读取论文 → 提取章节 → 总结内容 → 生成大纲 → 创建 PPT → 保存文件。

### 7.6 MCP 插件系统

通过 MCP Hub 实现插件化工具调用，支持无限扩展能力。已规划插件如下，未来可扩展邮件、数据库、天气、翻译等插件。

| 插件 | 功能 |
|------|------|
| File MCP | 文件读取、文件搜索、文件创建 |
| Browser MCP | 网页搜索、自动浏览 |
| Excel MCP | Excel 读取、数据分析、图表生成 |
| GitHub MCP | 仓库分析、README 生成 |
| 企业微信 MCP | 消息通知、任务提醒 |

---

## 8 Agent 架构

采用 LangGraph 构建多 Agent 工作流，架构如下：

- **Router Agent**：负责意图识别与任务分类，决定调用下游 Agent（Knowledge / Browser / Document / Workflow）。
- **Knowledge Agent**：负责 RAG 问答、文档检索、来源追踪。
- **Document Agent**：负责文件生成、文件转换、内容总结。
- **Browser Agent**：负责联网搜索、数据补充、自动化网页操作。
- **Workflow Agent**：负责多步骤任务编排、Agent 协作与状态管理。

---

## 9 长期记忆系统

系统记录用户的专业、项目经历、技术栈、常用目录与常用模板等信息。例如用户说"我的专业是人工智能"，系统自动写入长期记忆，以后生成简历时自动使用该信息。

---

## 10 权限系统

Agent 权限可配置，按风险等级分为四级：

| 等级 | 名称 | 允许操作 |
|------|------|----------|
| Level 0 | 只读 | 查询文件、搜索知识库 |
| Level 1 | 办公 | 创建 Word / Excel / PPT、生成报告 |
| Level 2 | 自动化 | 浏览器操作、下载文件 |
| Level 3 | 高风险 | 删除文件、发送消息（必须二次确认） |

---

## 11 多模态方案

第一版本不使用视觉大模型，采用 PaddleOCR 将图片转为文本后进行 Embedding 与 DeepSeek 分析。未来接入 Qwen-VL、MiniCPM-V 等视觉模型实现图片理解。
